# Матчевый движок: разбор и последовательный план

Отдельный трек от мира. Пока не идёт работа над миром, движок не перестраивается целиком: каждый
шаг ниже — один PR, после которого симуляция сравнивается с реальными демками тем же кодом
(`csmcore.matchstats`). Ни одна цифра здесь не является калибровкой: реальная выборка пока пустая.

## Что есть сейчас (`src/csmcore/engine.py`, 100 строк)

- Дуэль: логистическая кривая от разницы `duel_skill` (DUEL_SCALE=32), контекст (трейты,
  состояние, давление, химия, эко −8, дневная форма N(0, 4) на карту).
- Раунд: пока у обеих команд есть живые, случайный живой против случайного живого, один
  выстрел решает дуэль. Нет времени, бомбы, позиций, сторон, трейдов, гранат, оружия.
- Карта: MR12 до 13, пистолетки 1 и 13, проигравший пистолетку играет эко следующий раунд.
  Нет экономики дальше этого, нет смены сторон T/CT, нет овертайма MR3 (при 12:12 играется до
  13-го раунда победы, т. е. «овертайм» — один раунд).
- Результат: счёт, раунды с логом `X kills Y (p=..)`, выжившие. Сезон берёт из лога K/D и KPR.

Измерено на 400 картах топ-30 клубов сгенерированного мира (`scripts/compare_sim_real.py`):

| метрика | симуляция | что это значит |
|---|---|---|
| kills_per_round | 7.47 | каждый раунд — полное уничтожение проигравших |
| loser_survivors | 0.00 | сейвов, взрыва бомбы и истечения времени нет |
| first_kill_round_win | 0.64 | открывающий фраг даёт 64 % раунда |
| pistol_next_round_win | 0.70 | победа в пистолетке → следующий раунд |
| eco_round_win | 0.30 | эко против полной закупки |
| kd_p10 / p50 / p90 | 0.73 / 1.00 / 1.32 | разброс K/D среди игроков |
| clutch_1v2_win / 1v3+ | 0.24 / 0.08 | первый оставшийся один против 2 / 3+ |
| overtime_share | 0.09 | доля карт 12:12 |

Реальные значения появятся, когда `scripts/demo_analysis.py` прогонит локальные демки.

## Данные: откуда брать демки

- HLTV хранит демки профессиональных матчей (архивы .rar со ссылкой со страницы матча). Из
  облачной песочницы hltv.org недоступен (прокси отвечает connect_rejected), поэтому автоматической
  загрузки нет; демки скачиваются вручную и кладутся на диск. Перед любым автоматическим
  скачиванием нужно проверить условия использования HLTV.
- demoparser2 0.42.0 (PyPI, Rust + Python): `parse_event`, `parse_ticks`, `parse_grenades`,
  `parse_header`, `parse_player_info` и др.; результаты — pandas DataFrame. Используется в прототипе.
- awpy 3.1.0 (PyPI): надстройка над demoparser2 с готовыми таблицами раундов, убийств, гранат и
  статистикой (ADR, KAST, рейтинг). Полезна для перекрёстной проверки наших подсчётов.
- Прототип не прогонялся на настоящей демке (её нет в песочнице). Имена полей взяты из
  документации demoparser2; при первом реальном прогоне возможны мелкие переименования в
  `src/csmcore/demo_records.py`.

## Прототип

1. `scripts/demo_analysis.py match*.dem --out real.jsonl` — раунды, убийства с оружием и хедшотами,
   закупка команд (эвристика по стоимости снаряжения через 5 с после фризтайма: эко < 7500,
   форс < 20000), гранаты по командам, урон от гранат, закладка/дефьюз/взрыв, результат и причина.
   Команды отслеживаются по составу, а не по стороне, так что смена сторон не путает счёт.
2. `scripts/compare_sim_real.py --maps 400 --real real.jsonl` — одна и та же функция `metrics`
   считает симуляцию и реальность; метрики, которых движок не моделирует, отмечены N/A; при
   выборке меньше 2000 реальных раундов каждая строка помечена «не калибровка».
3. `tests/test_matchstats.py` проверяет разбор на фейковом парсере (смена сторон, убийство после
   конца раунда, тимкилл, смерть от мира, урон по своим) и что сравнение не выдаёт себя за подгонку.

## Последовательный план (каждый шаг — отдельный PR со сравнением до/после)

0. **Набрать выборку**: 30–50 карт топ-уровня одной версии игры, разных команд и карт. Без неё
   шаги ниже только меняют форму модели, а цифры остаются заглушками.
1. **Стороны T/CT и смена на 13-м раунде; овертайм MR3** (до 4 побед в овертайме, с ничьёй 3:3 —
   ещё один). Измеряется: overtime_share, rounds_per_map, доля побед CT по картам.
2. **Экономика**: деньги игроков, награды за победу и серию поражений, закупка по командному
   решению (полная, форс, эко, сейв). Измеряется: распределение buy types, eco_round_win,
   pistol_next_round_win, конверсия форсов.
3. **Время раунда, бомба и сейвы**: таймер, закладка, ретейк, дефьюз, решение сохранить оружие.
   Это первое, что сдвинет loser_survivors с нуля. Измеряется: bomb_plant_rate,
   defuse_after_plant, loser_survivors, kills_per_round.
4. **Контроль карты и трейды**: дуэли не «случайный против случайного», а по фазам (дефолт,
   выход на точку, ретейк), с шансом размена убитого товарища. Измеряется: first_kill_round_win,
   first_two_kills_round_win, доля разменов в пределах 5 с (метрику добавить вместе с шагом).
5. **Клатчи**: отдельная модель последнего игрока (время, бомба, хладнокровие из характера).
   Измеряется: clutch_1v2_win, clutch_1v3plus_win.
6. **Гранаты**: утилити как ресурс команды, влияние на дуэли входа и ретейка, урон. Измеряется:
   nades_per_round, utility_damage_per_round.
7. **Оружие и роли**: AWP у снайпера, пистолеты на эко, хедшоты от аима. Измеряется: kill_share_*,
   headshot_share, K/D по ролям.
8. **Адаптация по ходу карты**: тренер и капитан меняют план после серии проигранных раундов;
   связь с миром (давление, конфликты) через уже существующий контекст `ctx`.
9. **Статистика матча**: ADR, KAST, рейтинг — сверить с awpy на тех же демках.
10. **Подгонка** параметров (DUEL_SCALE, ECO_PENALTY и новых) только после шагов 0–3, по
    отложенной части выборки, с отчётом об ошибке. До этого в коде и документах не пишется
    «откалибровано».

Не трогается до своего шага: сезонный код вызывает только `play_map`, так что каждый шаг меняет
внутренности движка при той же сигнатуре и той же детерминированности по seed.
